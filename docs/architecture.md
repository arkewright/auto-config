# 从运行记录到内核配置

一个 C 源文件是观测单位，一个 Kconfig 选项是决策单位。主机准备采集内核，板端产生运行记录，主机再构建无插桩的候选内核。

## 构建与数据流

1. 主机入口读取 `.env`。基线版与采集版采用相同的起始配置和板级调整。采集版为指定源码生成 Clang 编译包装器，构建树外控制模块，并将清单、基线和覆盖记录留在 `profile/campaign/`。
2. 采集内核自启动起在内存中记录命中。板端的控制模块提供 `/dev/kconfig-trace`；负载完成后，用户冻结窗口，把快照传回主机。
3. 主机处理器根据快照和授权策略给出配置请求。候选构建运行 `olddefconfig`，确认实际配置与决策一致，然后用普通 Clang 编译并打包。基线和候选都不含采集插桩和控制模块。

三个角色使用不同的内核发行后缀，分别安装在版本化路径。部署只负责安装；[实板教程](board.md)说明如何选择内核、启动负载和安排模块加载。

## 观测对象

清单的每一行记录文件编号、配置名、模块名、策略和源码路径。自动映射识别 Kbuild 中能直接归属到配置项的 C 文件。复杂聚合对象由板级维护者提供清单；同一选项的各个成员采用相同策略。

[前端插件](../plugin/README.md)在选定文件的普通函数入口插入带编号的调用。编译收据给出插入点数；真实对象引用本次探针，且 Kbuild 归属与登记相符时，才计为有效覆盖。配置项有已编译却遗漏的成员，或任何登记文件缺乏覆盖时，处理器保留它。只有确认探针能记录命中，才把未命中当作负载未使用的证据。

## 时间窗口

采集内核在编译 `init/init_task.c` 时包含内建记录端，使启动早期即可计数。树外模块只控制采集和导出。命中表按文件编号索引原子状态字，探针不分配内存、不睡眠、不写内核日志。

| 命中位 | 记录的执行 |
|---|---|
| 启动 | `start` 之前的普通执行，包含进入业务就绪点前的用户空间预热。 |
| 负载 | 从 `start` 到 `stop` 的普通执行，范围是整台机器。 |
| 初始化 | 初始化回调同步调用的普通函数，与前两类分开。 |

插件跳过显式初始化段和退出段。记录端通过 `initcall_start` 和 `initcall_finish` 按任务跟踪同步调用，支持嵌套、睡眠和处理器迁移。中断和独立异步工作不继承初始化标记；跟踪钩子注册前的普通调用按启动执行记账。每次启动有一个窗口，停止后可重复读取冻结快照。

## 配置决策

每次采集构建生成随机标识，写入内核和快照。同一构建的多份快照可按位取并集，再按配置项聚合。启动命中优先保护选项；`keep`、覆盖不足以及清单外的选项保持原值。

| 授权 | 可提出的改变 |
|---|---|
| `drop` | 启动和负载均未命中时，可关闭已启用的选项。 |
| `defer` | 启动未命中且模块名明确时，可将内建项改成模块。负载命中不妨碍就绪后加载。 |

初始化位解释执行来源，不单独授权裁剪。负责板级设备注册、恢复路径等不可缺省的选项应设为 `keep`。终端审阅可以撤回建议；重新启动候选并回放业务，才能知道这份配置是否满足实际负载。文件格式见[配置处理器](../processor/README.md)。
