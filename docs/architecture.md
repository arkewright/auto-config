# 内核裁剪架构

裁剪分三步：观察组件在何时使用，按板级授权生成配置，再用新内核验证原负载。源文件是采集单位，Kconfig 选项是决策单位。

| 阶段 | 输入 | 输出 |
|---|---|---|
| 建立采集构建 | 目标源码、完整基线、板级清单 | 采集内核、外部驱动和本次构建的覆盖记录。 |
| 采集 | 启动过程、业务负载、采集命令 | 每个登记文件的启动、负载和初始化命中。 |
| 审阅 | 基线、策略、覆盖记录和快照 | 请求配置、变更理由和延迟模块名称。 |
| 构建与回放 | 审阅方案和目标 Kconfig | 无插桩候选内核、完整配置和按依赖排序的模块路径。 |

## 源文件与构建身份

板级清单将源文件编号关联到配置项、模块和策略。同一个选项可以登记多个文件；这些文件使用同一模块名和策略。自动发现从直接 Kbuild 规则起草清单，复杂聚合、条件编译和功能归属由维护者审计。

编译包装器按绝对源码路径选中目标文件。Clang 在入选函数入口插入带文件编号的调用，提交记录插入点数量的编译收据。构建结束后，工具核对对象中的探针符号引用和真实模块归属。缺少目标对象、没有保留探针、归属冲突或存在已编译但未登记的成员，都会使对应选项失去裁剪资格。

每次采集构建生成一个随机标识，写入清单目录、探针链接名和快照。采集内核使用专属发行后缀。处理器只合并标识相同的快照；QEMU 加载模块前核对模块与内核的发行版本。采集到候选构建期间使用同一份源码、基线和清单；改动后重新采集。

## 内建记录端与树外控制模块

内建函数从启动早期就要记录命中，因此采集内核在编译 `init/init_task.c` 时包含内建记录端。记录端持有命中表并导出接口。树外模块注册 `/dev/kconfig-trace`，负责启动、停止和读取采集；卸载控制模块后，探针仍指向内建记录端。两部分源码都维护在 `driver/`，候选内核按常规方式编译。

## 时间窗口

每个文件记录三个独立命中位：

| 命中位 | 记账规则 |
|---|---|
| 启动 | `start` 前的非初始化执行，包括用户空间预热。 |
| 负载 | 进入负载阶段后至冻结前的非初始化执行。 |
| 初始化 | 由初始化回调同步调用的普通函数。 |

插件排除初始化段和退出段。内建记录端通过 `initcall_start` 和 `initcall_finish` 按任务追踪同步调用链，处理嵌套、睡眠和处理器迁移。中断与独立异步任务不继承当前任务的初始化标记；跟踪钩子注册前的普通调用按启动执行记录。采集覆盖整机，快照不含进程名、调用参数或函数地址。

命中表按编号索引原子状态字。重复命中已置位的阶段直接返回，首次置位使用比较交换；探针不分配内存、不睡眠，也不写日志。开始和停止命令逐项推进状态，停止后旧写入不能穿过冻结边界。每次启动采集一个窗口，初始化钩子不可用或任务槽耗尽时拒绝采集。

## 从命中到候选配置

先按位合并同一次构建的快照，再按配置项合并登记文件。启动命中、覆盖不足、范围外选项和 `keep` 策略均保持原值。其余选项按授权继续判断：

- `drop`：启动和负载均未命中时，建议关闭。
- `defer`：启动未命中、模块名明确且已启用模块支持时，建议改为模块或保留现有模块；允许负载命中。

初始化位用于解释执行来源。设备注册、早期安全策略和恢复等要求由板级清单设为 `keep`。登记文件的覆盖只描述观测范围，设备固件、数据表和未回放的路径须在清单审计中评估。

候选构建核对身份、策略与原值，运行 `olddefconfig`，并比较全部配置项。配置值被依赖改写或产生未授权的连带变化时，停止发布。构建成功并解析模块硬依赖后，输出完整 `.config` 和加载顺序。`m` 决定模块构建形式，实际加载时刻由[板端回放](usage.md#采集回放和比较)安排。
