# 从运行记录到内核配置

一个 C 源文件是观测单位，一个 Kconfig 选项是决策单位。主机准备采集内核，板端产生运行记录，主机再构建无插桩的候选内核。

## 构建与数据流

1. 主机入口读取 `.env`。基线版与采集版采用相同的起始配置和板级调整。采集版为自动发现的源码生成 Clang 编译包装器，构建树外控制模块，并将清单、基线和覆盖记录留在 `profile/campaign/`。
2. 采集内核自启动起在内存中记录命中。板端的控制模块提供 `/dev/kconfig-trace`；负载完成后，用户冻结窗口，把快照传回主机。
3. 主机处理器根据快照和授权策略给出配置请求。候选构建运行 `olddefconfig`，确认实际配置与决策一致，然后用普通 Clang 编译并打包。基线和候选都不含采集插桩和控制模块。

三个角色使用不同的内核发行后缀，分别安装在版本化路径。部署只负责安装；[实板教程](board.md)说明如何选择内核、启动负载和安排模块加载。

## 观测对象

采集构建在 `drivers`、`fs`、`net`、`sound` 和 `kernel/configs.c` 中识别直接绑定，例如 `obj-$(CONFIG_IKCONFIG) += configs.o`。自动生成的 `scope.tsv` 每行记录文件编号、配置名、模块名或 `-`、策略和源码路径。例如，`e1000.o` 由多个对象链接而成，没有同名的 `e1000.c`。这类聚合对象和不能直接归属的条件规则不在观测范围，编辑器保留原值。

[前端插件](../plugin/README.md)在入选文件的普通函数入口插入带编号的调用。编译收据给出插入点数；目标对象引用本次探针且 Kbuild 归属与登记相符时，才计为有效覆盖。若清单外的已编译对象属于同一组件，或它的编译依赖引用了此开关，覆盖就不完整。例如，串口早期启动文件没有命中，并不能排除普通串口驱动使用了同一个控制台开关。

## 时间窗口

采集内核在编译 `init/init_task.c` 时包含内建记录端，使启动早期即可计数。树外模块只控制采集和导出。命中表按文件编号索引原子状态字，探针不分配内存、不睡眠、不写内核日志。

| 命中位 | 记录的执行 |
|---|---|
| 启动 | `start` 之前的普通执行，包含进入业务就绪点前的用户空间预热。 |
| 负载 | 从 `start` 到 `stop` 的普通执行，范围是整台机器。 |
| 初始化 | 初始化回调同步调用的普通函数，与前两类分开。 |

插件跳过显式初始化段和退出段。记录端通过 `initcall_start` 和 `initcall_finish` 按任务跟踪同步调用，支持嵌套、睡眠和处理器迁移。中断和独立异步工作不继承初始化标记；跟踪钩子注册前的普通调用按启动执行记账。每次启动有一个窗口，停止后可重复读取冻结快照。

## 配置决策

每次采集构建生成随机标识，写入内核和快照。自动分析合并同一构建的快照，再按配置项聚合。默认策略 `auto` 只处理覆盖完整、在采集基线中已启用且有可见配置提示的开关。

| 普通执行命中 | 自动建议 |
|---|---|
| 启动阶段命中 | 保留原值。 |
| 仅负载阶段命中 | 模块支持已启用、开关为三态且模块名明确时，使用 `m` 并列入就绪后的加载清单；否则保留原值。 |
| 两个阶段均未命中 | 提议关闭，依赖要求保留时撤回建议。 |

初始化位单独记录。需要保留设备注册、故障恢复等未被负载覆盖的能力时，将对应开关写入强制意见文件。

处理器将自动建议作为一个整体放入外部解析器导出的依赖图中检查。例如，已使用的驱动依赖两个能力中的任意一个时，只需保留一个满足条件的能力。如果驱动和能力都未使用，可以一起裁剪。报告区分运行命中、依赖保留、手动决定和强制意见。

编辑器以强制意见为准，允许暂存冲突，但只有满足导出约束的配置才能应用。候选构建再由原生 `olddefconfig` 核对实际值；业务是否仍然可用，由候选回放检验。操作和文件格式见[配置编辑器](../processor/README.md)。
