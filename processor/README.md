# 配置编辑器

在主机取回快照后运行 `./kcfg --plan`。左列是采集内核的原值，右列是当前请求值；`*` 和高亮标出差异。第一次打开时，只叠加强制意见，不会自动裁剪。按 `a` 分析，按 `d` 只看差异，按 `A` 应用。

## 固定板级要求

将必须使用的值写进普通文本文件，在 `.env` 中指定 `FORCE_CONFIG=/data/board-required.config`。每行一项，例如：

```text
CONFIG_EXT4_FS=y
CONFIG_E1000=m
CONFIG_E1000E=n
```

带 `LOCK` 的选项始终采用文件中的值，重新分析、手动编辑、撤销和重开草稿都不能改变它。强制或手动关闭曾经命中的选项，会在报告中注明覆盖了运行证据。互相矛盾的要求可以保存在草稿里，但不能应用：例如，强制保留的驱动依赖一项被强制关闭的能力，须修改意见文件后重新打开。

## 操作

| 按键 | 作用 |
|---|---|
| `/`，输入名称后回车 | 按名称过滤，忽略大小写。`n`、`N` 跳到下一项、上一项；Esc 清除过滤。 |
| `j`、`k`，`gg`、`G` | 上下移动，跳到首行或末行。Ctrl-d、Ctrl-u 移动半页。 |
| `i` 后按 `y`、`m` 或 `n` | 修改选中项。布尔项只接受 `y` 和 `n`；字符串和数值可查看原值。 |
| `a`、`r`、`u` | 开始自动分析；释放选中项的手动决定；撤销上一步。一次分析作为一次操作撤销。 |
| `d`、`c`、`?` | 切换差异视图，定位依赖冲突，打开帮助。 |
| `s` 或 `:w` | 保存草稿并继续编辑。 |
| `A` 或 `:wq` | 检查当前配置，成功后生成候选方案并退出。 |
| `q` | 退出而不应用；有未保存的编辑时先确认。 |

草稿位于 `$WORK/plan.draft`，只记录手动决定和是否已启动分析。再次打开时，编辑器用当前快照、强制意见和依赖图恢复配置。应用写入新的 `$WORK/plan/`，不覆盖上一份结果；再次应用到同一位置前先移走旧方案。`./kcfg --plan --batch` 不读草稿，直接分析并应用。

## 分析依据

- `profile/campaign/baseline.config` 是原配置；`scope.tsv` 的五列依次为文件编号、配置名、模块名、策略和源码路径。`coverage.tsv` 记录每个文件的有效插入点数。缺失覆盖和完整覆盖下的零命中是两种不同的证据。
- `TRACE` 和 `EXTRA_TRACES` 指定同一构建的快照。处理器分别合并启动、负载和同步初始化命中。在完整覆盖下，`drop` 允许关闭启动及负载均未命中的选项，`defer` 允许把启动未用且模块名明确的组件推迟加载，`keep` 保留原值。
- `DEPENDENCY_GRAPH` 留空时，主机使用 `uv` 运行外部 Kconfig 解析器，按采集架构和基线导出依赖图。指定已有[解析器导出文件](dependencies.md)时，编辑器直接读取，无需解析源码。分析按整份配置检查依赖表达式；保留依赖项的理由与运行命中分开显示。
- 手动决定一直有效，直到按 `r` 释放或撤销。自动分析开启后，更改手动决定也会更新其他自动建议。显式指定 `m` 只代表编译为模块，只有采集证据和 `defer` 策略支持的模块才列入延迟加载清单。

## 应用结果

`requested.config` 是完整的候选配置请求。`changes.tsv` 列出原值和请求值，`overrides.tsv` 记录所有手动和强制决定，`report.tsv` 解释证据和理由，`modules-load.late` 每行一个待延迟加载的模块。候选构建以目标源码运行 `olddefconfig`，实际值与请求不符时指出选项并停止。重新启动候选并回放负载，可检验此配置是否适合该板。
